## 真实服务冒烟验证

在运行中的服务（3001）上执行完整闭环：

1. 创建申请 → `待审批`，生成 3 个待处理节点
2. 节点 1 批准（备注"初审通过"）→ `待审批`
3. 节点 2 批准 → `已批准`
4. 执行分发 → `已分发`，批次库存正确扣减
5. 另一申请驳回 → `已驳回`，节点 1 已驳回、节点 2/3 已终止
6. 重新提交 → `待审批`，生成第 2 轮 3 个待处理节点，第 1 轮记录完整保留

存量数据回填验证（幂等）：

| 存量状态 | 回填结果 |
| --- | --- |
| 待审批 | seq1~3 待处理 |
| 已批准 | seq1/2 已通过、seq3 待处理 |
| 已分发 | seq1~3 均已通过 |
| 已驳回 | seq1 已驳回、seq2/3 已终止 |

## 结论

三节点审批链、驳回与重新提交、全轮次记录查询、状态响应标记与存量回填全部验证通过；前端生产构建（`tsc -b && vite build`）通过，前后端联调正常。
