# Requirements Document: 分发共享 · 全节点审批记录

Updated: 2026-09-28

## Introduction

分发模块当前为单节点审批：一条申请仅一次"批准/驳回"动作，备注挂在主记录上，无法体现多角色会签、无法追溯每个节点的审批人与意见。本功能将分发审批升级为三节点审批链：

- 每个申请自动携带固定审批链：库管员初审 → 库负责人审批 → 分发执行；
- 每个节点记录审批角色、审批人、备注说明（可选）与操作时间；
- 任一节点可驳回，驳回后申请人可重新提交（开启新一轮审批）；
- 全节点记录可查询（含历史轮次），节点状态有差异化视觉标记。

## Glossary

- **分发申请**：种质资源分发请求，单号 `DR-*`
- **审批轮次（round）**：一次完整的审批链执行；重新提交产生新一轮，历史轮次记录保留
- **审批节点**：轮次内的固定步骤：seq 0 提交事件、seq 1 库管员初审、seq 2 库负责人审批、seq 3 分发执行
- **节点状态**：`已提交`（seq 0 事件）/ `待处理` / `已通过` / `已驳回` / `已终止`（流程未到达即终止）
- **应用状态**：`待审批` / `已批准` / `已驳回` / `已分发`（沿用现状，由当前轮次节点状态推导）

## Requirements

### R1 三节点审批链

**User Story:** AS 库管员/库负责人, I want 按固定节点顺序逐级审批并执行分发, so that 职责分离且全程留痕。

#### Acceptance Criteria

1. WHEN 分发申请创建成功, 系统 SHALL 生成第 1 轮审批链：提交事件（seq 0）+ 3 个「待处理」节点（库管员初审、库负责人审批、分发执行）
2. WHEN 当前节点被批准, 系统 SHALL 记录审批角色、审批人、备注（可为空）与操作时间，将节点置为「已通过」
3. WHEN 节点 2 被批准, 系统 SHALL 将申请状态置为「已批准」
4. WHEN 节点 3（分发执行）被批准, 系统 SHALL 执行库存扣减、批次状态重算与必要的库存预警，并将申请状态置为「已分发」
5. IF 对非当前可操作节点发起审批, 系统 SHALL 以 409 拒绝并返回当前应操作节点
6. WHILE 申请状态非「已批准」, 执行分发 SHALL 被拒绝

### R2 节点驳回

**User Story:** AS 审批人, I want 在任一节点驳回申请并说明原因, so that 申请人明确被拒环节与理由。

#### Acceptance Criteria

1. WHEN 任一当前节点被驳回, 系统 SHALL 记录驳回原因（必填）与审批人，将该节点置为「已驳回」，同轮后续未处理节点置为「已终止」，申请状态置为「已驳回」
2. IF 驳回原因为空, 系统 SHALL 以 400 拒绝该请求

### R3 重新提交

**User Story:** AS 申请人, I want 被驳回后补充说明并重新提交, so that 无需重建申请即可再次走审批流程。

#### Acceptance Criteria

1. WHEN 申请状态为「已驳回」且申请人重新提交, 系统 SHALL 生成新一轮审批链（含重新提交事件，可附说明），申请状态置为「待审批」
2. WHILE 申请状态非「已驳回」, 重新提交 SHALL 被拒绝（409）
3. 历史轮次的节点记录 SHALL 完整保留可查

### R4 审批记录查询

**User Story:** AS 申请人/管理员, I want 查看申请的全节点审批记录, so that 掌握审批进展与各方意见。

#### Acceptance Criteria

1. WHEN 查询分发申请列表或详情, 系统 SHALL 内嵌按轮次、seq 排序的全部节点记录（含历史轮次）
2. WHEN 查询种质详情下的分发列表, 系统 SHALL 同样内嵌节点记录

### R5 状态响应标记

**User Story:** AS 页面用户, I want 不同状态以不同颜色标记, so that 一眼识别节点进展。

#### Acceptance Criteria

1. WHILE 前端展示审批节点, 系统 SHALL 对「已提交/待处理/已通过/已驳回/已终止」使用五种不同颜色的状态标记
2. WHILE 前端展示申请列表, 系统 SHALL 展示当前轮次审批进度（已通过节点数 / 3）

### R6 存量数据兼容

**User Story:** AS 系统, I want 启动时为存量申请补齐节点记录, so that 历史数据同样可追溯。

#### Acceptance Criteria

1. WHEN 系统初始化且存量申请缺少审批记录, 系统 SHALL 按当前状态回填第 1 轮：提交事件 + 待审批→3 节点待处理；已批准→节点 1/2 已通过、节点 3 待处理；已分发→3 节点均已通过；已驳回→节点 1 已驳回（原因取原备注）、节点 2/3 已终止
2. 回填 SHALL 幂等，重复启动不产生重复记录

## Out of Scope

- 动态配置审批链（节点/角色增删）
- 审批消息通知（站内信/短信）
- 角色权限强校验（审批人由前端选择/默认填充）
